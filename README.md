# Verified Agent Synthesis

This repository implements a full synthesis pipeline for **Constrained Decoding Strategies (CSDs)**.
A strategy is generated by an LLM as Dafny code, formally verified, compiled to Python, then evaluated on benchmark tasks with parser-constrained decoding.

The project is organized so the core workflow is explicit:

- `synthesis/generate`: create/refine strategy bodies.
- `synthesis/verify`: verify Dafny contracts and compile verified code.
- `synthesis/evaluate`: run benchmark evaluation and feed failures back into synthesis.

## Repository Layout

- `synthesis/`: core pipeline package.
- `synthesis/generate/`: generation prompts, rationale extraction, and generator logic.
- `synthesis/verify/`: Dafny verification/compilation wrappers.
- `synthesis/verify/library/`: Dafny template/library used for generated strategies.
- `synthesis/evaluate/`: evaluator, feedback loop orchestration, runtime helpers, and benchmarks.
- `synthesis/evaluate/benchmarks/`: benchmark-specific dataset, environment, generation, and metrics code.
- `synthesis/evaluate/grammars/`: Lark grammar files used by constrained decoding.
- `synthesis/evaluate/syncode/`: vendored Syncode dependency for DFA-mask parser acceleration.
- `dafny/`: local Dafny runtime/tooling bundle.
- `generated/`: synthesis outputs (one folder per synthesized CSD run).
- `baselines/`: baseline result artifacts (organized by old CSD/model/benchmark pairs).

## Pipeline Stages

The synthesis loop runs these stages repeatedly until thresholds are met or iteration budget is exhausted:

1. **Generate**: produce an initial or refined Dafny strategy body.
2. **Verify**: run Dafny verification on full assembled source.
3. **Compile**: compile verified Dafny to Python.
4. **Evaluate**: score strategy behavior on benchmark samples.
5. **Refine**: if a stage fails, feed structured failure context back into generation.

## Output Contract

Runtime artifacts now live at the repo root under two durable directories:

- `generated/`
- `baselines/`

Each synthesis run creates a dedicated folder inside `generated/`:

- `generated/<output_name>_<timestamp>_<token>/dafny/`
- `generated/<output_name>_<timestamp>_<token>/python/`
- `generated/<output_name>_<timestamp>_<token>/results/`

This makes it easy to inspect strategy source, compiled runtime code, and reports without mixing files across runs.

## Quick Start

1. Install Python dependencies.

```bash
pip install -r requirements.txt
```

2. Verify Dafny is available.

```bash
dafny --version
```

3. Run synthesis.

```bash
CUDA_VISIBLE_DEVICES=1,2 python -m synthesis.run_synthesis \
  --task "Solve math word problems step by step, writing each arithmetic computation inside << >> delimiters." \
  --dataset gsm_symbolic \
  --generation-model "Qwen/Qwen2.5-Coder-7B-Instruct" \
  --eval-model "Qwen/Qwen2.5-Coder-7B-Instruct" \
  --max-iterations 5 \
  --min-accuracy 0.3 \
  --min-syntax-rate 1.0 \
  --eval-sample-size 10
```

## Dafny Files Used by Synthesis

- `synthesis/verify/library/GeneratedCSD.dfy`
  - Template that receives generated strategy code.
- `synthesis/verify/library/VerifiedAgentSynthesis.dfy`
  - Core verified interfaces/contracts/helpers strategies rely on.

## Notes for Contributors

- Keep synthesis prompts as controlled-study inputs: task + formal tool contracts only.
- Do not replace Syncode DFA-mask validity checks with brute-force vocabulary parsing.
- If you change benchmark contracts, update both runtime code and benchmark READMEs so experiments remain auditable.
